## 2. 画面

PC でもスマホと同じ幅（430px まで）の一列で出す。日付は 10/15(木)、練習の時刻は 13:00〜17:00 の形で書く。

ページのアイコンは青地に白いカレンダーとチェックで、練習室予約のピアノのアイコンと同じ青・白・紺でそろえる。ブラウザのタブには public/favicon.svg、iPhone のホーム画面には public/apple-touch-icon.png（180px 四方、角は丸めない）を使う。

画面の言葉は次のようにそろえる。決定のボタンは「登録する」「保存する」「送信する」のように動詞で終える。行ごとの操作（複製・直す・消す）はアイコンだけのボタンにし、消すは赤のごみ箱にする。何もないときの表示は「練習日はまだありません」「団員はまだいません」の形にする。

出欠の色は、出席が青、遅刻・早退が薄い青、欠席が橙、未回答が灰色の輪。入力のボタン、札、人数の点、帯のすべてでこの決まりを使う。

### 2.1 登録とログイン

はじめに開くのはログインの画面。暗証番号の欄の下に小さく「はじめての方は 登録」があり、押すと登録の画面に移る。登録の画面の下には「登録済みの方は ログイン」がある。パスキーのボタンのさらに下に、目立たない「管理者の方」と「プライバシーポリシー」が並ぶ。登録の画面のいちばん下にも「プライバシーポリシー」がある。

i ボタンは練習室予約システムと同じ作り。細い線の丸に i を描いた小さなボタンで、説明は薄い灰色の小さな札（ダークモードでは濃い灰色）で出す。指の端末では押すと出て、もう一度押すか、ほかの場所を押すと消える。マウスのある端末ではボタンの上にしばらく止めると出て、外れると消える。札は画面の端からはみ出さない位置に出し、画面を動かすと消える。

- 登録: 合言葉、姓と名（別々の欄）、パート、暗証番号（4〜8桁の数字）を入れて登録する。氏名は姓と名をスペースなしでつないだもの（例: 宮教太郎）で、画面にはこの形で出す。姓と名の中のスペースは除く。同じ氏名はほかの人が使えない。2026-10-15 より前に登録した人は、氏名の中のスペースで姓と名に分け、スペースがなければ全部を姓に入れた（設定で直せる）。
- ログイン: 氏名（一つの欄。スペースの有無は問わない）と暗証番号の欄と「暗証番号でログイン」を上に置き、親指で押しやすい画面の下の端に「パスキーでログイン」を大きく出す（パスキーを使えるブラウザだけ）。押すと端末の指紋・顔・画面ロックで本人を確かめ、氏名も暗証番号も入れずに入れる。合言葉は登録のときだけ入れる。
- 登録のすぐあとと、パスキーを持っていない人が暗証番号でログインしたすぐあとに「パスキーを作りますか」の画面を出す。「作る」で作ってホームへ、「あとで」でそのままホームへ進む。見出しの横の i ボタンで「指紋や顔、画面ロックでログインできるようになります。暗証番号でのログインも使えます。」が出る。設定のパスキーの欄の i ボタンでも同じ。
- ログイン画面の一番下の「管理者の方」から、管理用パスワードでログインできる（URL の末尾に `#admin` を付けても同じ）。

合言葉がまだ決まっていないときは、登録の画面に「まだ登録を受け付けていません。」と出る。ログインの印は端末に残り、180日使わなければログインし直しになる。

### 2.2 下のタブ

ログインしていると、画面の下に練習日・一覧・管理のタブがアイコンだけで出る（読み上げには名前を伝える）。管理のタブはパートリーダーと管理者にだけ出る。管理用パスワードで入ったときは、一覧と管理だけ。

### 2.3 練習日（ホーム）

上の帯の左（ほかの画面では団の名前がある所）の切り替えで、月のカレンダー（左。はじめはこちら）とリストを行き来する。最後に見た方を端末ごとに覚え、次に開いたときもそちらを出す。リストは出欠を答える練習日だけを、カレンダーは出欠をとらない予定も含めた団の予定の全部を出す。カレンダーの下に選んだ日の予定が少なくとも1件見えるよう、iPhone 17 の Safari で上下のバーが出ている高さに収まる大きさにしてある。

- カレンダー: iPhone のカレンダーにならい、月のマスにその日の予定の種類を色つきで並べる（角の丸い札で三つまで。四つ以上は二つと「他n件」。名前は札の端で薄れて切れる）。色は団で配っていた Excel の月のカレンダーにそろえ、合奏が赤、本番・演奏・リハーサルなどが青紫（出席の青と見分けられるよう紫に寄せる）、そのほかの練習（個人／パートなど）が黄。出欠をとらない予定（授業・祝日など）は色を付けず灰色の文字で出す。練習の名前の頭には自分の出欠の色の点（出席は青、遅刻・早退は薄い青、欠席は橙、未回答は灰色の輪）を付け、カレンダーの下にこの色の見本を出す。カードに入れず画面の幅いっぱいに出し、上に大きな月（その上に小さく年）、右に前後の月のボタンと、今日以外を選んでいるときだけ「今日」のボタンを置く。カレンダーを左右になぞっても前後の月に替わる（左へなぞると次の月）。なぞるあいだ日付のマスが指についてきて、少ししか動かさなければ元に戻る。画面の左右の端から始めたなぞりは iPhone の戻る操作に任せて月は替えず、縦に動かしたときはふつうに画面が流れる。この動きは一覧のカレンダー、練習日を足すシートのカレンダー、管理の練習日でも同じ。週の区切りは横線だけ。土日の日付は灰色。今日の日付は赤い丸。日を押すと灰色の丸で選ばれ、カレンダーの下にその日の予定を時刻の順に並べる（時刻のないものは終日）。練習の行には自分の出欠が出て、押すと出欠の入力に進む。行の右のボタンはリストと同じく、チェックで出席、点三つで遅刻・早退・欠席のシートが開く。出欠をとらない予定の行は押せない。はじめは今日、月を替えたらその月の最初の予定の日を選ぶ。過ぎた日の予定は薄く出す。
- リスト: 各行の左にカレンダーと同じ予定の色の縦線を付ける。今日以降でいちばん近い練習日を「次の練習」として一つ大きく出し、その先を月ごとに区切って日付の順に並べる。右に自分の出欠（出席・遅刻・早退・欠席・未回答。遅刻と早退は時刻も）を出す。まだ答えていない日の札は枠つきで目立たせる。これからの日は、札の代わりに右へ二つの丸いボタンを並べる。右端のチェックを押すとその場で出席になり（出席の色で塗る）、もう一度押すと未回答に戻る。画面は送るのを待たずに変わり、送れなかったら元に戻して知らせる。その左の点三つのボタンを押すと、下からシートが開き、遅刻・早退・欠席を選んで時刻や理由を書いて送る。遅刻・早退・欠席と答えた日は、点三つの代わりにその札を出し、押すと同じシートが開く。まとめて出席にする仕組みは、一日ずつ責任を持って答えてもらうため置かない。行の本体を押すと出欠の入力に進む。過去の練習日は下のボタンで開く。同じ日に練習が二つ以上ある（パート練習と合奏など）ときは、それぞれ別の行になり、出欠もそれぞれに答える。次の練習の日に二つあれば、両方を「次の練習」に出す。

練習日・一覧・出欠の入力・CSV で扱うのは出欠をとる練習日だけで、出欠をとらない予定はカレンダーにだけ出る。団で配っていた月のカレンダーは、このカレンダーで代える。

練習日を押すと出欠の入力に進む。右上の氏名（下向きの印つき）を押すと、設定・プライバシーポリシー・ログアウトが出る。

設定では姓・名とパートを変えられる。その下の畳んだ「暗証番号」の欄を開き、今の暗証番号と新しい暗証番号（4〜8桁の数字）を入れて「変える」を押すと暗証番号が変わり、ホームに戻る。変えると、いま使っている端末のほかのログインは切れる（パスキーはそのまま使える）。今の番号を5回続けて間違えると、ログインと同じく10分止まる。下のパスキーの欄に、自分のパスキーを作った日と最後に使った日が並び、右のごみ箱のアイコンで消せる。「パスキーを作る」で足せる（一人10個まで）。

### 2.4 出欠の入力

戻るボタンは日付の見出しと同じ行にある。この画面と設定の画面にも下のタブを出し、練習日のタブでも戻れる。ブラウザの履歴にも一つ積むので、iPhone で画面の左端から右へなぞる操作や Android の戻るボタンでも練習日に戻る。出席・遅刻・早退・欠席の四つから選ぶ。ボタンには出欠の色の点が付き、選ぶとその色で塗られる。出席は押しただけで送り、ホームに戻る。遅刻と早退を選ぶと時刻の欄（任意）が、欠席を選ぶと理由の欄（任意、200字まで）が出て、「送信する」で送る。遅刻・早退の時刻は誰にでも見える。i ボタンで「理由を読めるのは本人とパートリーダーと管理者だけです。」が出る。過ぎた練習日は変えられない（ボタンが押せない）。

### 2.5 パート別の出欠

練習日を上の並びかカレンダーのボタンから選ぶ。上の並びで同じ日が二つ以上あるときは、月と曜日の代わりに開始の時刻（なければ種類）を出して見分ける。カレンダーでは、押すたびにその日の次の練習に移る。最初は今日以降でいちばん近い練習日。日付を押すと、選んだ印はすぐその日に移る。一度開いた日は前に読んだ内容をすぐ出してから裏で読み直し、初めての日は読み終わるまで前の日の内容を薄くして出しておく。読んでいるあいだも別の日を押せて、最後に押した日だけを出す。上の並びは描き直しても横の位置を保つ。日付を選ぶと、その日が並びの真ん中に来るまで滑らかに動く（端末で動きを減らす設定にしているときは一度に動く）。出席・遅刻と早退・欠席・未回答の人数（名前の前に色の点）と帯、全体・弦・管打の絞り込み、パートごとの一覧を出す。団員のいないパートは出さない。パートごとの一覧には全員の名前を一人ずつ並べ、出席・遅刻・早退・欠席・未回答の順にする。

パートリーダーと管理者には、欠席の人の理由が出る（記入がなければ「理由の記入なし」）。「理由を隠す」で隠し、「理由を見る」でまた出す。団員には自分の理由だけが出る。

### 2.6 管理

上の切り替えで、練習日・団員・パート・記録を行き来する。パートリーダーには練習日と団員だけが出る。

- 練習日（パートリーダーと管理者）: タブには練習日の一覧だけを出す。一覧は一月ずつ日付の順に出し、はじめは今月を出す。月の見出しの右の矢印か、一覧を左右になぞって前後の月に替える（左へなぞると次の月。動きはホームのカレンダーと同じ）。過ぎた月もこうして戻れば見られ、過ぎた日は薄く出す。今月以外を出しているときは「今月」のボタンで戻る。月の見出しには件数を、各行の左に予定の色の縦線を付ける。見出しの右には今日から先の日数を出す。見出しの右の＋で足すシートを、各行の鉛筆で直すシートを、一覧の上に下から重ねて開く。シートは右上の×、外側を押す、iPhone の左端からなぞる戻る、Esc で閉じ、閉じると一覧の同じ位置に戻る。足すシートでは、カレンダーで日付を何日でも押して選び、種類（合奏・分奏などの候補あり、自由に書ける）、開始と終了の時刻（どちらも空でよい。本番など時刻を出さない日は空にする）、メモをまとめて付けて足す（一度に100日まで）。「出欠をとらない」に印を付けると、授業や祝日などカレンダーに載せるだけの予定になる（種類は必ず入れる）。一覧ではその行に「出欠なし」の札を付ける。種類の候補は合奏・個人／パート・分奏・リハーサル・演奏会・本番・授業・休み。曜日を押すと、その月のその曜日のうち今日以降の日をまとめて選ぶ（全部選ばれていれば外す）。すでに練習日のある日には点が付く。足したあとも種類・時刻・メモは欄に残る。一覧の各行の右にある三つのアイコンのボタンで、左から順にその日の種類・時刻・メモを足す欄に写して足すシートを開く（複製）、一つずつ直す、その日の出欠ごと消す。ボタンに文字は出さず、読み上げ用の名前だけを付ける。時刻の欄は iPhone の時刻選びの「リセット」で空に戻せる。
- 団員: 団員はパートごとにまとめ、パートの並び順に出す。団員の役割（団員・パートリーダー・管理者）を変える。左の印で団員を選び、「n人を消す」でまとめて消す。消すと出欠の記録・ログイン・パスキーも消える。暗証番号を忘れた人は、行の鍵のアイコンで再設定する。確かめたうえで6桁の仮の暗証番号を作り、一覧の上に大きく出すので、本人に伝えてもらう。本人はそれでログインし、設定で自分の番号に変える。仮の番号は画面を離れるか次の操作をすると消え、あとから見る方法はない。再設定しても出欠の記録・ログイン・パスキーはそのまま残り、誤りで止まっていたのも解ける。パートリーダーの団員のタブには、氏名と役割だけが並び、鍵のアイコンは役割が団員の人にだけ出る（パートリーダーと管理者の暗証番号は管理者だけが再設定できる）。最後の管理者は、団員としてのログインからは消せない・外せない（管理用パスワードのログインからはできる）。いちばん下に合言葉の欄を畳んで置き、開くと変えられる（4〜64文字。変えても、すでにログインしている人はそのまま使える）。合言葉が未設定のときは開いた状態で出す。
- パート: 弦と管打のパートを並べ、人数を出す。団員のいないパートは右のごみ箱のアイコンで消せる（団員のいるパートのアイコンは薄くなり押せない）。名前（英数字8文字まで）と弦か管打を選んで足すと、その組の最後に入る。
- 記録: CSV の書き出し。すべての練習日と団員の組み合わせを1行ずつ（日付・種類・開始・終了・氏名・パート・出欠・時刻・欠席理由・回答日時）。Excel で開けるよう先頭に BOM を付ける。「年度で消す」は、終わった年度（4月から翌年3月）を選んで「書き出して消す」を押すと、その年度の分の CSV を保存させてから、確かめたうえでその年度の練習日と出欠を消す。

### 2.7 プライバシーポリシー

ログインの前（ログインと登録の画面の下）からも、ログインのあと（右上の氏名のメニュー）からも開ける。URL の末尾に `#privacy` を付けても開く。左上の戻るボタンか、ブラウザの戻る操作で元の画面に戻る。上に制定日（と改定日）、その下に見出しごとのカードで文を出す。文は public/privacy.js にあり、預かる情報、暗証番号とパスキーの置き方、見える範囲、置く場所と扱える人、漏れを防ぐしくみ、消し方を短く書いている。ログインのあとはこの画面にも下のタブを出す。

## 3. サーバー

### 3.1 呼び出し

`POST /api`、本文は `{ "action": "…", "params": { … } }`、ログインの印は `Authorization: Bearer …`。応答は `{ ok: true, … }` か `{ ok: false, code, message }`。呼び出せるのは画面のサイト（wrangler.toml の ALLOWED_ORIGIN、https://miyakyo-orchestra.github.io）からだけで、ほかのサイトからの呼び出しは断る。ログインの印を Authorization に入れて送るので、ブラウザは先に OPTIONS で確かめてくる。

| action | 使える人 | 内容 |
| :--- | :--- | :--- |
| info | 誰でも | パートの一覧、登録を受け付けているか |
| register | 誰でも（合言葉） | 団員の登録 |
| login | 誰でも | 団員のログイン（応答の hasPasskey でパスキーを持っているかを返す） |
| passkeyLoginOptions・passkeyLogin | 誰でも | パスキーでのログイン |
| adminLogin | 誰でも（管理用パスワード） | 管理用パスワードでのログイン |
| home | ログイン中 | 自分、今日の日付（日本時間）、練習日、自分の出欠 |
| logout | ログイン中 | ログインの印を消す |
| roster | ログイン中 | 練習日ごとの全員の出欠。理由は本人・パートリーダー・管理者にだけ入れる |
| answer | 団員 | 出欠の入力（status は attend・late・early・absent。late と early は at に時刻。none は答えを消して未回答に戻す） |
| updateProfile | 団員 | 氏名とパートの変更 |
| changePin | 団員 | 自分の暗証番号の変更（pin に今の番号、newPin に新しい番号。ほかの端末のログインを切る） |
| passkeys・passkeyRegisterOptions・passkeyRegister・passkeyDelete | 団員 | 自分のパスキーの一覧・作成・削除 |
| adminData・saveDay・saveDays・deleteDay | パートリーダー・管理者 | 練習日の管理（adminData はパートリーダーには練習日と、団員の氏名・パート・役割だけを返す。saveDays は練習日をまとめて足す） |
| resetPin | パートリーダー・管理者 | 暗証番号の再設定。応答に6桁の仮の番号を入れて返す（パートリーダーは役割が団員の人だけ） |
| setRole・deleteMember・deleteMembers・setPassphrase・addPart・deletePart・exportCsv・deleteYear | 管理者 | 管理の操作（exportCsv と deleteYear は year で年度を選ぶ） |

### 3.2 守り

- 暗証番号と合言葉は PBKDF2（20000回）で元に戻せない形にして置く。ログインの印は SHA-256 にして置く。
- パスキーは WebAuthn の仕組みで、端末の中の秘密の鍵による署名を、登録のときに受け取った公開鍵で確かめる。サーバーに置くのは公開鍵だけ。相手のサイトは ALLOWED_ORIGIN（rpId はその名前、https://miyakyo-orchestra.github.io なら miyakyo-orchestra.github.io）で、ほかのサイトからの署名は通らない。チャレンジは5分で切れ、一度しか使えない。端末で本人を確かめた印（UV）がないものは通さない。作るときに認証器の証明（attestation）は求めない。
- 暗証番号を5回続けて間違えると、その団員は10分ログインできない。設定で暗証番号を変えるときの今の番号の誤りも、同じ回数に数える。
- 再設定の仮の暗証番号は、サーバーの乱数で作る。置くのはほかの暗証番号と同じく元に戻せない形だけで、仮の番号そのものは再設定した人への応答にしか出さない。
- 登録のない氏名でログインしようとしたときも、暗証番号の照合と同じだけの計算をしてから断る。かかる時間から登録の有無を知られないため。止められている団員は、正しい番号を入れても10分たつまで入れない。
- 管理用パスワードは、入力と設定のそれぞれを SHA-256 にしてから比べる。
- 呼び出しの本文は 64KB まで。CSV では、= + - @ などで始まる値の頭に ' を付け、表計算ソフトで式として動かないようにする。
- 合言葉・管理用パスワード・ログインの氏名か暗証番号・パスキーでのログインを、同じ接続元から合わせて10回続けて間違えると、10分止める。

### 3.3 データ

Durable Object（名前 main の1つだけ）の SQLite に置く。書き込みは1件ずつ順番に処理される。Cloudflare が自動で控えを取り、30日前までの状態に戻せる。表と列は次のとおりで、作り方と古い形からの直し方は store.js の init にある。

| 表 | 列 |
| :--- | :--- |
| members（団員） | id、name（姓と名をつないだ氏名。重複不可）、sei、mei、part、role（member・officer・admin）、pin（暗証番号を PBKDF2 にしたもの）、created_at、failures と locked_until（暗証番号の誤りの回数と止める期限） |
| days（練習日と予定） | id、date、kind（種類）、st と en（開始と終了の時刻。空でよい）、note（メモ）、noentry（1 なら出欠をとらない予定） |
| answers（出欠） | day_id と member_id の組で一件、status（attend・late・early・absent）、reason（欠席理由。書いたままの文字）、at（遅刻・早退の時刻）、updated_at |
| sessions（ログインの印） | token（印を SHA-256 にしたもの）、member_id（空なら管理用パスワードでのログイン）、created、last_used（1日に1回だけ書き直す） |
| passkeys | id（認証器が決める番号）、member_id、jwk（公開鍵）、alg、created_at、last_used |
| kv（小さな値） | passphrase（合言葉を PBKDF2 にしたもの）、parts（管理画面で変えたパートの一覧）、gate:接続元の IP（誤りの回数。10分で消える）、pk:チャレンジ（パスキーの操作中だけ。5分で消える） |

答えていない日は answers に行がなく、画面では未回答として出す。未回答に戻すときは行を消す。団員を消すと、その人の answers・sessions・passkeys も消える。練習日を消すと、その日の answers も消える。自動で消えるのは、180日使われなかったログインの印と、期限の切れた kv の値だけ。

入力の上限は、姓と名がそれぞれ30文字、種類20文字、メモ100文字、欠席理由200文字、合言葉4〜64文字、暗証番号4〜8桁の数字、パートは30まで、パスキーは一人10個まで、練習日をまとめて足すのは一度に100日まで。

## 4. パート

はじめは弦が Vn・Va・Vc・Cb（1stと2ndは分けない）、管打が Fl・Ob・Cl・Fg・Hr・Tp・Tb・Tuba・Perc。`src/store.js` の PARTS に書いてあり、管理画面で変えると kv の parts に置いた一覧を使う。以前 Vn1・Vn2 で登録した人は、サーバーが起きたときに Vn に直る。

## 5. 役割と使えること

| | 団員 | パートリーダー | 管理者 | 管理用パスワード |
| :--- | :--- | :--- | :--- | :--- |
| 自分の出欠を入れる、設定、パスキー | できる | できる | できる | できない（団員ではないため） |
| 一覧で全員の出欠と遅刻・早退の時刻を見る | できる | できる | できる | できる |
| 欠席理由を読む | 自分のだけ | 全員 | 全員 | 全員 |
| 練習日と予定を足す・直す・消す | できない | できる | できる | できる |
| 暗証番号を忘れた人の再設定 | できない | 団員だけ | 全員 | 全員 |
| 役割の変更、団員の削除、合言葉、パート、CSV、年度で消す | できない | できない | できる | できる |

役割の確かめはサーバー（store.js の PRIVATE に書いた、操作ごとに要る立場）で行い、画面のタブの出し分けは見た目だけ。管理用パスワードでのログインは管理者として扱い、最後の管理者を消す・外すこともできる。

## 6. まだ手当てしていないこと

- 仮の暗証番号でログインした人に、番号を変えるよう促す仕組みはない。変えるかどうかは本人に任せている。
- 姓と名に分ける前から登録していて氏名にスペースがなかった人は、姓の欄に全部が入り名が空のまま。この人が設定で保存すると「姓と名を入れてください」で止まり、名を自分で分けて入れる必要がある。
- 自動のテストは store.js を通したもの（パスキーの登録とログインを含む）だけで、画面（app.js）のテストはない。
