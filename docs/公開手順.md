# 公開手順（はじめて公開するとき）

画面は GitHub Pages、サーバーは Cloudflare Workers に、GitHub Actions が公開する。最初の一回だけ、次の作業を人の手で行う。

## 1. Cloudflare の API トークンとアカウント ID

練習室予約システムと同じ Cloudflare のアカウントを使う。Worker は初回の公開のときに自動で作られるので、Cloudflare の画面で Worker やアプリケーションを作る必要はない。

1. 右上の人のアイコンからプロフィールを開き、API トークンの画面で「トークンを作成する」を押す。ひな形の Cloudflare Workers の編集用（Edit Cloudflare Workers）を選び、アカウントのリソースで自分のアカウントを選んで作る。トークンは一度しか表示されないので、すぐに控える。
2. Workers & Pages の画面の右側に出ているアカウント ID を控える。

## 2. GitHub の Secrets

リポジトリ `miyakyo-orchestra/attendance` の Settings > Secrets and variables > Actions で、次の三つを登録する。

| 名前 | 値 |
| :--- | :--- |
| `CLOUDFLARE_API_TOKEN` | 1 で作ったトークン |
| `CLOUDFLARE_ACCOUNT_ID` | 1 で控えたアカウント ID |
| `ADMIN_PASSWORD` | 管理用パスワード。長めの文字列にし、管理者だけで共有する |

## 3. GitHub Pages の公開元

リポジトリの Settings > Pages で、Build and deployment の Source を「GitHub Actions」にする。

## 4. 公開と最初の設定

1. main に push する（プルリクエストをマージする）。Actions の「サーバーを Cloudflare に公開」と「画面を GitHub Pages に公開」が動く。
2. サーバーの URL（`https://miyakyo-orchestra-attendance.<サブドメイン>.workers.dev`）が public/config.js の API_URL と同じか確かめる。違えば直して push する。
3. https://miyakyo-orchestra.github.io/attendance/#admin を開き、管理用パスワードでログインする。
4. 管理画面で合言葉を決め、練習日を足す。
5. 自分も団員として登録し、管理用パスワードのログインから自分の役割を「管理者」にする。以後は団員としてログインすれば管理画面も使える。
6. 合言葉と URL を団員に知らせる。

## 管理用パスワードを変えるとき

GitHub の Secrets の `ADMIN_PASSWORD` を書き換えて、Actions の「サーバーを Cloudflare に公開」を手で動かす。

## Cloudflare のアカウントを引き継ぐとき

アカウントの持ち主が卒業する前に、後任を Manage Account > Members から Administrator として招待する。管理者は常に二人以上にしておく。
