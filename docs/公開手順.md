# 公開手順（はじめて公開するとき）

GitHub の Organization `miyakyo-orchestra` のリポジトリから、GitHub Actions が Cloudflare Workers に公開する。最初の一回だけ、次の作業を人の手で行う。

## 1. Cloudflare のアカウント

1. 担当者が自分のメールアドレスで Cloudflare のアカウントを作る（無料のプラン）。
2. 左のメニューの「Workers & Pages」を一度開き、workers.dev のサブドメイン（例: `miyakyo-orchestra`）を決める。公開先は `https://miyakyo-orchestra-attendance.<サブドメイン>.workers.dev` になる。
3. 「Manage Account > Members」から、もう一人（後任の候補や責任者）を Administrator として招待する。管理者を常に二人以上にしておく。

## 2. API トークンとアカウント ID

1. 右上の人のアイコン →「My Profile」→「API Tokens」→「Create Token」で、ひな形「Edit Cloudflare Workers」を選び、Account Resources を自分のアカウントにして作る。表示されたトークンを控える（一度しか表示されない）。
2. 「Workers & Pages」の画面の右側に出ている Account ID を控える。

## 3. GitHub の Secrets

リポジトリ `miyakyo-orchestra/attendance` の Settings > Secrets and variables > Actions で、次の三つを登録する。

| 名前 | 値 |
| :--- | :--- |
| `CLOUDFLARE_API_TOKEN` | 2 で作ったトークン |
| `CLOUDFLARE_ACCOUNT_ID` | 2 で控えたアカウント ID |
| `ADMIN_PASSWORD` | 管理用パスワード。長めの文字列にし、管理者だけで共有する |

## 4. 公開と最初の設定

1. main に push するか、Actions の「Cloudflare に公開」を手で動かす。終わると公開先の URL が記録に出る。
2. `公開先の URL/#admin` を開き、管理用パスワードでログインする。
3. 管理画面で合言葉を決め、練習日を足す。
4. 自分も団員として登録し、管理用パスワードのログインから自分の役割を「管理者」にする。以後は団員としてログインすれば管理画面も使える。
5. 合言葉と URL を団員に知らせる。

## 管理用パスワードを変えるとき

GitHub の Secrets の `ADMIN_PASSWORD` を書き換えて、Actions の「Cloudflare に公開」を手で動かす。
