# 設計メモ（第一段階）

宮城教育大学オーケストラの練習出欠システムの設計をまとめる。計画書とモックアップの確定（2026-10-15）を受けて書いた。決めたことと理由、まだ決めていないことを分けて書く。動きの細部は docs/仕様書.md に書き、こちらは判断の記録として残す。

## 何を解決するか

今は LINE の日程調整を弦と管打に分けて使っている。イベントの取り違え、本名と結びつかない表示名、パートで絞れない一覧、グループに流しにくい欠席理由の四つが不便の元になっている。このシステムでは、全団員が一つの画面で練習日ごとに出欠を入れ、本名とパートで並んだ一覧を見られるようにし、欠席理由は本人とパートリーダーの人だけが読めるようにする。

## 判断の基準

担当者が卒業しても止まらないことを一番の基準にする。具体的には次の四つを守る。

- 年度替わりなどに必ずやらなければならない作業を作らない。誰も触らなくても動き続ける。
- お金がかからない。Cloudflare の無料プランの範囲で動かす。
- 権限を一人に集めない。GitHub の Organization と Cloudflare のアカウントは、どちらも管理者を二人以上にする。
- データはいつでも CSV で書き出せる。仮に止まっても、記録を持って LINE に戻れる。

## 構成

画面は GitHub Pages、データは Cloudflare に置く。練習室予約システム（miyakyo-music/yoyaku）と同じ分け方で、Durable Object の SQLite を正本にする形を、スプレッドシートの写しを除いてそのまま使う。

- GitHub Pages が画面（public/ の HTML・CSS・JS）を配る。団員が開く URL は https://miyakyo-orchestra.github.io/attendance/ になる。
- Cloudflare Workers は呼び出し（/api）だけを受ける。画面のサイトからの呼び出しだけを受け付ける。Worker は練習室予約システムと同じ Cloudflare のアカウントに置く（2026-10-15 決定）。初めは画面も Worker から配る案だったが、workers.dev の URL に個人のアカウント名が入るため、団員が目にする URL を GitHub Pages にした。
- データは Durable Object（名前 main の1つだけ）の中の SQLite に置く。書き込みは1件ずつ順番に処理されるので、同時に送っても食い違わない。Cloudflare が自動で控えを取り、30日前までの任意の時点に戻せる。
- main ブランチに push すると、GitHub Actions が画面を GitHub Pages に、サーバーを Cloudflare に公開する。公開に要るのは、リポジトリの Secrets に入れる Cloudflare の API トークンとアカウント ID、管理用パスワード、それに Pages の公開元の設定だけ。
- 外部のライブラリは画面にもサーバーにも使わない。書体だけ Google Fonts から IBM Plex Sans JP を読む（Safari では使わず、iPhone 標準の書体で出す）。

無料プランでの見込み。Workers の無料枠は1日10万回の呼び出しで（画面のファイルは GitHub Pages が配るので数えない）、団員が100人、練習日が月に十数回、一人が1日に数回開く程度なら、1日あたり数百から千回台に収まる。Durable Object の SQLite も無料プランで使える形（new_sqlite_classes）にする。

## 本人確認

計画書で未決だった「一人ずつのログインか、共通パスワードか」は、両方を組み合わせる形にする。

団員はまず、団で共有する合言葉を入れる。合言葉は団の外の人が入ってこないための鍵で、管理者が管理画面で決め、いつでも変えられる。合言葉を知っている人は、氏名・パート・自分で決める暗証番号（4〜8桁の数字）を登録できる。二台目の端末や、ブラウザのデータを消したあとは、氏名と暗証番号でログインし直す。初めはログインにも合言葉を求めていたが、毎回入れるのは手間が大きいため、合言葉は登録のときだけにした（2026-10-15）。代わりに、暗証番号の誤りも同じ接続元から続けば10分止め、氏名を変えながら番号を試し続けることを防ぐ。一度ログインした端末では、半年使わないまで入れ直しは要らない。

この形にした理由は三つある。共通パスワードだけでは誰が誰かを区別できず、欠席理由を本人にだけ見せることができない。メールや LINE でのログインは、送信の仕組みや LINE の開発者登録が誰か個人のアカウントに結びつき、引き継ぎの弱点になる。暗証番号なら外部のサービスに頼らずに済む。

パスキーでのログインも選べるようにし、こちらを勧める（2026-10-15）。パスキーは端末の指紋・顔・画面ロックで入れ、番号を覚えなくてよく、ほかのサイトに入力させられる心配もない。外部のサービスにも頼らない。ただ、LINE の中で開いた画面では動かないことがあり、機種変更で iPhone と Android をまたぐと引き継がれず、借りた端末でも使えない。そのため暗証番号でのログインは控えとして残し、ログイン画面ではパスキーを先に出し、登録や暗証番号でのログインのすぐあとにパスキーを作るよう勧める形にした。サーバー側の確かめは src/passkey.js に、外部のライブラリを使わずに書いた。

暗証番号は元に戻せない形（PBKDF2）にして置く。5回間違えるごとに、その団員はしばらくログインできなくなる（初めは10分。2026-10-28 から、止まるたびに倍にし、最長1日。回数は正しく入れるか再設定するまで数え続ける）。初めの形は止めるたびに回数を0に戻していたため、10分に5回ずつ試せば、4桁の番号は2週間ほどで当てられた（セキュリティ監査 2026-10-28）。合言葉やログインの入力ミスも、同じ接続元から続けば10分止める。団員は設定で自分の暗証番号を変えられる。忘れた団員は、パートリーダーか管理者が管理画面で仮の番号に再設定する（2026-10-20）。初めは消して登録し直してもらう形で、出欠の記録まで消えていた。仮の番号は管理する人が決めるのではなくサーバーが乱数で作り、そのとき一度だけ画面に出す。弱い番号を選ばれず、あとから誰かが見返すこともできない。パートリーダーが再設定できるのは役割が団員の人だけにした。パートリーダーが管理者の番号を変えてなりすますと、団員の管理まで手に入るため。自分で変えたときはほかの端末のログインを切り、再設定のときは切らない。再設定は本人が忘れて困っている場面で、本人の端末のログインまで切る理由がないため。

管理用パスワードでのログインは、そのときのパスワードに結び付けておき、パスワードを変えるか消すと切れるようにした（2026-10-28）。以前は印が180日残り、前の代の担当者やパスワードを見た人が印を持っていると、パスワードを変えても管理者のまま入れた。卒業で担当が替わるたびにパスワードを変えれば、それだけで前の人の管理用ログインが切れる。結び付きは印とパスワードをつないだ SHA-256 にしたので、データが漏れても印を知らなければパスワードを割り出せない。

## 役割と、欠席理由を読める人

役割は三つにする。

- 団員: 自分の出欠を入れ、全員の出欠（出席・欠席・未回答）をパート別に見られる。欠席理由は自分のものだけ見える。
- パートリーダー: 団員にできることに加えて、全員の欠席理由を読め、練習日の登録と削除ができる。どの団員をパートリーダーにするかは管理者が決める。
- 管理者: パートリーダーにできることに加えて、団員の役割の変更と削除、合言葉の変更、パートの足し引き、CSV の書き出しと年度ごとの片付けができる。

欠席理由は、サーバーが読む人の役割を確かめてから返す。権限のない人への応答には理由を含めないので、画面のコードを読まれても漏れない。

最初の管理者は、Cloudflare の秘密の設定に入れる管理用パスワード（ADMIN_PASSWORD）で管理画面に入り、自分を管理者にする。管理者が全員卒業しても、Cloudflare か GitHub を触れる人が管理用パスワードを入れ直せば、管理画面に戻れる。

## 画面

モックアップ（2026-10-15 確定）に合わせる。書体は IBM Plex Sans JP だけ（2026-10-25 から Safari では iPhone 標準の書体。Apple のガイドラインに合わせるため）、色は出席が青、欠席が橙、未回答は灰色の輪。ライトとダークは端末の設定で切り替わる。画面に説明文は書かず、どうしても要る説明だけを i ボタンの中に入れる（練習室予約システムと同じ決まり）。

- 団員の画面: 初回登録とログイン、練習日のリストと月のカレンダーの切り替え、練習日ごとの出欠入力（欠席なら任意の理由）。
- パート別の出欠: 練習日を選び、全体・弦・管打で絞り込んで、パートごとの出欠を見る。パートリーダー以上には理由も出る。
- 管理画面: 練習日、団員、合言葉、CSV の書き出し。

## パートと練習日

パートは Vn・Va・Vc・Cb を弦、Fl・Ob・Cl・Fg・Hr・Tp・Tb・Tu・Perc を管打として始め、管理画面から足し引きできる。ヴァイオリンは1stと2ndを分けない（2026-10-15 決定）。

練習日はパートリーダーと管理者が登録する。1日ずつでは手間なので、カレンダーで何日でも選び、種類と時刻をまとめて付けて足せるようにした（2026-10-15）。日付、種類（合奏・分奏など）、開始と終了の時刻、メモを持つ。過ぎた練習日の出欠は、団員からは変えられない。

## 名簿の扱い

共有ドライブの団員名簿は取り込まない。団員が自分で氏名とパートを登録する。名簿の個人情報がこのシステムに一切渡らない。

## 2026-10-15 に決めたこと（しばらく使って見直す）

最初の版を見たうえで、次の案をいったん採用した。使ってみて、また直す。

- 遅刻と早退を足し、何時ごろかを書けるようにした。時刻は誰にでも見せる。遅刻・早退は出席の仲間として薄い青で表す。
- 出席は押しただけで送る。遅刻・早退・欠席だけ、欄を埋めて送信する。
- パート別の出欠への入口を、画面の下のタブにした。管理画面も中を練習日・団員・パート・記録のタブに分けた。
- パート別の一覧は、出席の人を人数だけにまとめ、欠席と未回答などを先に見せる。のちに、パートごとに全員の名前を並べる形に変えた（今の動きは仕様書の 2.5）。
- パートリーダーは欠席理由を読めるうえに、練習日の登録もできる。パートリーダーにする範囲は団で決め、管理画面で一人ずつ付ける。
- 回答の締め切りは設けず、練習日が過ぎるまで変えられる。
- 卒業生や古い記録は、管理画面で団員をまとめて消し、年度ごとに書き出してから消す。自動では消さない。
- パートは管理画面から足し引きできる。Tuba を足した。
- 2026-10-21 Tuba の表記を Tu にした（団の希望）。
- 2026-10-29 iOS 27 でホーム画面に置いて開くと、上の帯がぼやけていた。iOS 26 からのホーム画面のアプリは、上の端に一色で塗った帯が貼りついていないと、上の端からしばらくの範囲をぼかす。上の帯を地の色で塗って上に貼りつけた。このぼかしは iPhone のホーム画面のアプリでしか出ないので、効いたかどうかは iPhone で確かめる。
